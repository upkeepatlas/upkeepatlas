## Mechanics

- Public ownership key: \`public/27441d201328388b746929fd572c8a7068f5ee8a.txt\`, text content matches its name.
- Route list is constrained to the verified production origin \`https://upkeepatlas.pages.dev\`; preview domains are excluded.
- After a successful \`main\` branch **Build and quality** run, GitHub Actions checks out that exact SHA, determines affected page paths, waits until Cloudflare serves that deployed SHA, checks the live key file, then notifies Bing with one JSON batch.
- Changed URL filtering avoids unnecessary submissions on docs-only/CI-only/style-only changes and can notify about removed routes.
- \`workflow_dispatch\` supports a manual full-site submission for recovery, but frequent resubmission of unchanged content is discouraged.
- All URLs in the first batch were canonical published pages; no preview, staging, draft or user-submitted arbitrary URLs.

## What the HTTP 202 means

The response confirms Bing received the URL notifications and may still be validating the ownership key. It **does not mean any of the 15 pages are indexed**. This is consistent with the IndexNow protocol's documented response behavior.

The next external observation is Bing Webmaster Tools → IndexNow reporting and Index Explorer/index coverage, as Bing processes the notifications. Sitemap submission and Bing Webmaster site verification remain separate tasks.

## Maintenance and relocation

If Upkeep Atlas moves to a custom domain, update the canonical production origin and IndexNow host/key on that domain, publish the key file there, and verify its production deployment before any new notifications. Detailed instructions: [docs/INDEXNOW.md](../INDEXNOW.md).
