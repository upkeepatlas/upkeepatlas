## Existing-site inspection and exact gap
At main `5b70bcfcc124877ea61877a45d230f2aa45fc3a6`, `src/lib/routes.mjs` manually enumerated 15 routes. `src/pages/sitemap.xml.ts`, `scripts/check-seo.mjs` and `src/lib/indexnow.mjs` all reused that same list. Adding a new Astro tool or Markdown guide could therefore produce a working page that was **not** registered in the sitemap, SEO audit or IndexNow. The dynamic guide index and guide pages already render content from `src/content/guides`, and must not be replaced or duplicated.

## Original technical contribution
- Discover canonical routes from real `src/pages/**/*.astro`, F001's Markdown guide files and legacy guide slugs at build time; reject unregistered dynamic templates and unsafe/duplicate guide slugs.
- Keep existing `/guides/[slug]` route and existing paths intact; auto-render relevant related-guide navigation so homeowners can reach more current field notes from a guide detail.
- Compare built indexable `dist/**/index.html` paths to registry, and the canonical sitemap URLs to the same registry, rejecting silent omissions and unregistered pages.
- Compare prior Git-tree page paths and guide IDs for IndexNow removed-page notifications. Content additions select the new guide and its parent index rather than the whole site; docs-only commits do not trigger URL notifications.

**Important limitations:** The registry currently handles flat guide Markdown slugs matching the existing F001 dynamic route, not nested content directories or arbitrary parameterized Astro pages. New dynamic patterns fail the build until implemented explicitly; that is intentional, to avoid exposing routes absent from verification. No claim of guaranteed crawler inclusion or indexing.
