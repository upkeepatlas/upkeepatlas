# F003 — Licensed media intake and responsive delivery

Before adding an image, decide whether it teaches something that plain text or an existing SVG cannot. Do not use search-result thumbnails or manufacturer artwork without an explicit license.

1. Save a permitted original or third-party image under `public/assets/` only after verifying the **specific file** and permitted commercial use. Record one CSV row in `docs/production/assets.csv` for every image in that directory. Quote commas in CSV fields. Use the exact on-disk byte count and pixel dimensions, a source URL, creator, dated rights check, license name/URL and attribution requirement. `rights_check` is `original` for work created by the publisher or `verified` for third-party permission with linked evidence. A generic site license does not establish permission for every asset.
2. Prefer Astro's built-in `<Image />` with an imported local image from `src/assets/` for new raster content. Astro's image service creates optimized output and supports explicit responsive `widths` and `sizes`. Use `alt` and reserve dimensions; inspect generated HTML and actual transformed bytes. Images stored in `src/assets/` must also have a rights ledger entry before use; the current check covers public/assets and built HTML but does not yet inventory source imports. Until that extension, put third-party images in public/assets and optimize them before committing.
3. For a preoptimized public image, use `<img src="/assets/name.webp" alt="Meaningful description" width="..." height="..." loading="lazy" decoding="async" />`; use `srcset` and `sizes` only for actual separately generated files. Avoid fictitious responsive URLs. Leading imagery may load eagerly. SVGs require meaningful text alternatives if used as content images; decorative SVGs may use empty alt.
4. Run `npm run build && npm run check:media` locally or use the mandatory GitHub Actions check. It rejects unregistered public media, incomplete provenance, mismatched byte counts and built `img` elements lacking alt/intrinsic dimensions. It cannot independently prove a license is legally valid, judge image relevance, or measure performance on real devices; those require editorial review.
5. Do not remove attribution text or change a license without rechecking rights. When a media file changes, update its byte count and rights evidence. No third-party photos were added by F003.

Official technical references: https://docs.astro.build/en/guides/images/ ; https://developers.google.com/search/docs/appearance/google-images ; https://www.w3.org/WAI/tutorials/images/ .
